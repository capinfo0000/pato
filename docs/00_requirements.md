# 要件定義書 — pato岡山（仮）

- バージョン: 0.1（初版・設計フェーズ）
- 最終更新: 2026-08-12
- 対象リリース: MVP（patoコール先行 / Web・PWA / 岡山エリア限定）

---

## 1. 目的・背景

港区中心の「ギャラ飲み」をアプリ化した pato を参考に、**岡山エリアに限定**した
エンタメ会食マッチングサービスを立ち上げる。地方では供給（キャスト）密度が成否を
分けるため、エリアを岡山市中心部に絞り、**供給先行 → 需要 → マッチング**の順で
密度を作る。

### スコープ方針
- MVPは **patoコール（複数名の呼び出し）**のみ。コパト（1対1）は次フェーズ。
- クライアントは **Web（レスポンシブ / PWA）**。ネイティブアプリは後続。
- 決済・本人確認は外部ベンダを Adapter で抽象化し、差し替え可能にする。

---

## 2. 用語定義

| 用語 | 意味 |
|---|---|
| ゲスト | キャストを呼ぶ側の利用者（旧称:男性ユーザー相当。性別で限定しない） |
| キャスト | 呼ばれる側の利用者。審査通過が必要 |
| patoコール | 場所・時間・人数・クラスを指定し、複数名のキャストを呼ぶグループ型マッチング |
| コパト | 特定キャストと1対1で日程調整して会う指名型（次フェーズ） |
| ポイント | サービス内通貨。ゲストが購入し消費する（前払式支払手段の論点あり） |
| おひねり | 追加で任意に付与できるチップ的ポイント |
| クラス | キャストのランク（例: スタンダード / プレミアム / VIP） |
| エンタメスキル提供契約 | キャスト⇄ゲスト間で成立する契約。運営は当事者にならない |

---

## 3. アクターとロール

- **ゲスト**: 会食にキャストを呼ぶ。ポイント購入・呼び出し作成・合流・評価。
- **キャスト**: 審査申込・募集への参加表明・合流・報酬受取。
- **管理者(運営)**: 審査、通報対応、エリア/料金マスタ管理、精算管理。

認可はロールベース（`guest` / `cast` / `admin`）＋ Policy による所有権チェック。

---

## 4. 機能要件

### 4.1 共通 / アカウント
- FR-A01 会員登録（メール＋パスワード / SMS OTP）。
- FR-A02 ロール選択（ゲスト / キャスト）。1アカウント1ロールを基本とする。
- FR-A03 **本人確認（eKYC）**: 公的身分証＋顔認証。**未成年（18歳未満）は登録不可**。
  未確認ユーザーは呼び出し作成・参加ができない。
- FR-A04 プロフィール編集。
- FR-A05 退会（ポイント失効の明示同意を必須）。

### 4.2 キャスト審査
- FR-C01 審査申込（写真＋プロフィール）。
- FR-C02 二段階審査（第1:写真審査 / 第2:面談）。ステータス: `applied → photo_review → interview → approved / rejected`。
- FR-C03 承認後にクラス（スタンダード/プレミアム/VIP）を付与。
- FR-C04 審査基準・通過率は運営の内部指標。**外部公表値は「自己申告」と明示**（誇大表示をしない）。

### 4.3 patoコール（MVPの中心）
- FR-P01 ゲストが呼び出しを作成: エリア、集合場所、開始日時、所要時間（30分単位）、
  募集人数、希望クラス、希望のシチュエーション/キャストタイプ/スキル、予算（ポイント）、メモ。
- FR-P01b **利用場所制限**: レストラン・バー・公共施設等のみ許可。**鍵付き個室・ホテル・
  自宅・レンタルスペース等の密室は禁止**（安全確保・法務要件、`docs/04` 参照）。作成UIで
  場所種別を選択・検証する。
- FR-P02 作成時に**必要ポイントを与信（ホールド）**。残高不足なら作成不可。
- FR-P03 条件に合致するキャストへ募集を公開（プッシュ/一覧）。
- FR-P04 キャストが**自由意思で参加表明**（運営からの参加強制・指示は行わない）。
- FR-P05 募集人数に達したら成立（`matched`）。集合情報を双方に通知。
- FR-P06 合流・開始（`in_progress`）→ 終了（`completed`）。
- FR-P07 **延長**: 30分単位で追加ホールド・消費。
- FR-P08 **おひねり**: 5,000ポイント〜。キャストごとの配分指定、未指定なら均等分配。
- FR-P09 キャンセル: 成立前は無償、成立後・直前はキャンセルポリシーに従いホールド消費。
- FR-P10 深夜・指名・交通費などの加算項目（料金マスタで定義、MVPは深夜加算のみでも可）。
- FR-P11 **エリア別料金**: 料金はクラス×エリアで定義（pato も地方ほど安い）。岡山は「地方」
  水準で設定。`docs/03_decision_log.md` の料金表を参考値とする。
- FR-P12 **優先マッチング（指名）**: 特定キャストを指名して優先的にマッチ（追加料金）。
- FR-P13 **ミックス**: 希望クラスを混在で募集できる（マッチした組み合わせで課金）。
- FR-P14 **グループチャット**: 成立後に参加者を含むスレッドを自動生成（FR-M と連動）。
- FR-P15 **ファミリー（お気に入り）**: ゲストがキャストをお気に入り登録し再依頼しやすくする。

### 4.4 ポイント / 課金
- FR-PT01 ポイント購入（外部PSP経由。クレジット/デビット）。
- FR-PT02 **1有償ポイント = 1.2円相当**（税込）を基準に商品を定義。無償ポイントは1P=1円。
  消費順は**無償ポイントが先**。
- FR-PT03 ポイントは**払戻し・換金不可**、**有効期限は発行日から180日**（資金決済法の
  適用除外＝6ヶ月以内設定の根拠。`docs/04_legal_compliance.md` 参照）。
- FR-PT04 台帳（point_transactions）で全増減を記録。残高は台帳合算で算出。
- FR-PT05 ホールド（与信）→ 確定消費 / 解放 の3状態を扱う。
- FR-PT06 **課金モード2種**: 「自動支払い（利用の都度、登録カードで自動決済）」と
  「事前購入（ポイントを前払い購入）」。事前購入残高を超えた分は自動決済で補う。
- FR-PT07 **決済手段**: クレジット/デビットカード＋保有ポイント。銀行振込は将来検討。
  カード情報は自社保持せず PSP に委譲。
- FR-PT08 **定期購入（サブスク, 任意）**: pato の BOOST PASS 相当のパス商品。自動更新の事前告知
  （更新前）・解約手段・返金条件を特商法表記に明示（`docs/04` 参照）。MVPでは任意機能。
- FR-PT09 **返金ポリシー**: ポイント・パスは購入確定後・自動更新後の返金不可、日割りなしを明示。

### 4.5 メッセージ
- FR-M01 成立した呼び出し単位のスレッドでゲスト⇔キャストがやり取り。
- FR-M02 連絡先直交換・外部誘導・金銭直接請求を禁止（フィルタ＋通報）。
- FR-M03 **メッセージ一覧**: フィルタ（すべて／お気に入り／非表示）、ニックネーム検索、
  相手の在席状態・クラス・最終メッセージ時刻を表示。
- FR-M04 **コンシェルジュ（公式アカウント）**: 運営のシステムアカウントが案内・クーポン配布・
  時限オファーを送る。ユーザー同士のスレッドと区別（system ロール）。
- FR-M05 **キャンペーンバナー**: 一覧上部にクーポン還元等の告知（期間・対象・カルーセル）。
- FR-M06 **まとめてギフト**: 複数キャストへ一括でギフト（称賛ギフト/ポイントギフト）を送付。

### 4.6 評価・信頼・安全
- FR-T01 終了後に相互評価（星＋定型タグ）。
- FR-T02 **通報**（迷惑行為・規約違反・危険）。運営が確認しアカウント制裁。
- FR-T03 ブロック機能。
- FR-T04 NGワード/禁止行為の検知（メッセージ・プロフィール）。AI/ルールベースの不正検知で
  蓄積データからモニタリング（pato の独自AI不正検知に相当）。
- FR-T05 **SOS機能**: 利用中に緊急通報できるボタン。運営・緊急連絡へのエスカレーション。
- FR-T06 **24時間365日の監視・サポート窓口**（電話/メール）。
- FR-T07 **禁止行為の明文化と検知**: 現金手渡し・直接取引／他アプリ誘導・マルチ勧誘／密室
  （自宅・ホテル・鍵付き個室）利用／直前・無断キャンセル／タイマー停止・強制延長要求／
  性的サービスの示唆。違反はアカウント停止・退会。
- FR-T08 **年齢確認と児童誘引の検知**（出会い系規制法対応、`docs/04` 参照）。

### 4.7 キャスト精算（Payout）
- FR-PO01 完了した呼び出しからキャスト報酬を計上。
- FR-PO02 出金申請 → 運営承認 → 外部送金。サイクル・下限額はマスタで定義。
  参考（pato）: **通常は翌月末払い、即日/翌日振込の早期申請オプション**あり。現金手渡しは
  反社/マネロン/密室リスクのため自社では原則採用しない方針で検討。
- FR-PO03 精算明細の閲覧。
- FR-PO04 キャストは**個人事業主**（税は自己申告）。源泉/支払調書の要否を要確認。

### 4.8 管理（運営）
- FR-AD01 審査キュー管理。
- FR-AD02 通報対応・制裁。
- FR-AD03 エリア/店舗/料金/クラスのマスタ管理。
- FR-AD04 精算承認・売上/GMVダッシュボード。

### 4.9 体験・その他（pato公式ゲストページ準拠）
- FR-X01 **登録動線**: LINE連携 / 電話番号（SMS OTP）で開始。**登録なしでキャスト閲覧可**
  （会員登録・マッチング・メッセージは無料。課金はポイント購入時のみ）。
- FR-X02 **プライバシー既定**: 実名・電話番号・写真は既定で非公開。表示名で活動。
- FR-X03 **領収書発行**: 利用後にアプリ上でPDF等の領収書を発行（ビジネス利用向け）。
- FR-X04 **バッジシステム**: ゲストの振る舞い・利用実績に応じて称号バッジを付与。
  キャストからもゲストの会員プロフィールで閲覧可能。
- FR-X05 **グレードランクアップ**: 利用内容に応じ会員ステータスが上がり、特典が変わる。
- FR-X06 **つぶやき**: キャストが短文を投稿し、ゲストが反応（いいね）してメッセージ起点にできる
  （主にコパト導線。次フェーズ）。

### 4.10 探索・検索（ディスカバリ）
- FR-D01 **ホーム「呼ぶ」2導線**: `今すぐ呼ぶ`（パトコール＝エリア/合流予定時刻/設定時間/
  クラス×人数を指定）と `選んで呼ぶ`（キャストを選んで指名）。
- FR-D02 **待機キャスト数**の表示（今すぐ呼べる人数の可視化）。
- FR-D03 **絞り込み検索**: 活動エリア・出身地・年齢・身長・キャストタグ（スタイル/顔立ち/系統/
  髪型/職歴/楽しみ方/対応スキル 等）・クラス。
- FR-D04 **クラス×人数の複数指定**（例: ロイヤルVIP1名＋VIP1名）。ミックス課金と連動。
- FR-D05 サブバーティカル（例: **patoゴルフ**）をカテゴリで切替（MVPは通常patoのみ、拡張余地）。
- FR-D06 **在席/対応ステータス**: キャストに在席度（例: 今すぐ可/本日可/オフライン）と
  **合流中**（対応中で呼べない）を持たせ、一覧・カードに表示。
- FR-D07 **今日会えるキャスト**: 本日対応可能なキャストの横スクロール枠（クラス/年齢/エリア/
  一言/在席）。全件一覧への導線。
- FR-D08 **注文履歴**: 過去の呼び出し（パトコール/コパト）の履歴確認・再依頼。
- FR-D09 キャストカード共通要素: 写真・クラス・在席ドット・年齢・ニックネーム・エリア・一言。

### 4.11 ランキング・ゲーミフィケーション（供給の動機付け）
> pato の中核的な差別化。MVPでは最小（キャストKPI表示のみ）から始め、段階導入する。
- FR-G01 **キャストKPI**: 延長率・サービスリピート率・また会いたい率（星）を集計・表示。
- FR-G02 **ファンポイント**: キャスト独自評価スコア。ランキングの基礎。
- FR-G03 **ランキング**: ゲスト／キャスト別、期間別（昨日〜全期間）×カテゴリ×エリア。
  ゲストは自分の順位（圏外含む）を確認できる。
- FR-G04 **称号・大会**: 季節イベント（例: シンデレラレース＝合流時間/人数部門、天下統一戦＝
  リーグ/グループ順位）で称号を付与。
- FR-G05 **バッジ**: ゲストがキャストへ称賛バッジを送る（癒し系/キラキラ/ユーモア/歌姫 等、
  数量カウント）。加えてゲスト自身の実績バッジ・グレード（FR-X04/05）。
- FR-G06 **ギフト・イベント**（キャンペーン参加特典）。
- FR-G07 **クーポン**: 呼び出しに適用できる割引/付与ポイント。付与・失効・利用を台帳で管理。
- FR-G08 **友達招待コード（リファラル）**: 招待による特典付与。

### 4.12 オンボーディング・通知
- FR-O01 **利用準備チェックリスト**（例: 本人確認・支払い設定・プロフィールの 0/3 完了）。
- FR-O02 **お知らせ**（運営からの通知一覧）。プッシュ（Web Push）と連動。

## 5. 非機能要件

- NFR-01 **可用性**: MVPは単一コアサーバ + マネージドDB。稼働率目標 99.5%。
- NFR-02 **性能**: 主要画面 P95 < 800ms。呼び出し作成〜公開 < 2s。
- NFR-03 **セキュリティ**: OWASP Top10 対策。PII暗号化保存。TLS必須。監査ログ。
- NFR-04 **プライバシー**: 個人情報保護法準拠。本人確認書類は最小権限・保持期間管理。
- NFR-05 **決済/資金**: PCI DSS はPSPに委譲（カード情報を自社保持しない）。前払式支払
  手段の残高監視（基準日1,000万円超で届出義務、`docs/04` 参照）。
- NFR-06 **監査可能性**: ポイント・精算は台帳ベースで完全再現可能。
- NFR-07 **地域限定**: 岡山エリア外の呼び出し作成を抑止（エリアマスタで制御）。
- NFR-08 **年齢確認**: 18歳未満を確実に排除（eKYC必須）。

## 6. 主要ユースケース（patoコール）

```
[ゲスト] 呼び出し作成 → ポイント与信(ホールド)
    → [システム] 条件合致キャストへ公開
    → [キャスト] 参加表明（自由意思）
    → [システム] 定員成立 → 双方に集合情報通知
    → 合流・開始 → （必要なら延長） → 終了
    → ポイント確定消費 → キャスト報酬計上
    → 相互評価
```

例外: 成立前キャンセル（ホールド解放）／不成立で期限切れ（自動解放）／
成立後キャンセル（ポリシー消費）／通報発生（運営介入）。

---

## 7. スコープ外（MVPでは作らない）

- コパト（1対1指名）
- ネイティブアプリ（iOS/Android）
- 岡山以外のエリア展開
- キャスト間ランキング/イベント/婚活派生
- 複雑な動的価格（サージ）

## 8. 未決定事項（要ビジネス判断）

1. **キャスト報酬レート（テイクレート）**。pato 非開示のため、`docs/06_pricing_model.md` で
   **作業デフォルト40%（キャスト60%）**を設定済み。最終値はビジネス判断で確定。
2. クラス別の具体料金（30分単価）。**岡山＝地方水準**を `docs/06_pricing_model.md` に確定
   （プレミアム3,000P等）。深夜/指名の加算率は各+20%を仮置き（要確定）。
3. 使用する決済PSP・eKYCベンダの選定。
4. キャンセルポリシーの具体的料率（直前/無断の扱い）。
5. サービス正式名称・ブランド。
6. 定期購入（BOOST PASS 相当）を MVP に含めるか。
7. 現金手渡し精算を採用しないか（リスク観点で原則不採用を推奨）。
