# セキュリティ方針 — pato岡山（仮）

本サービスは **決済・本人確認書類・位置情報**を扱う。侵害されたときの被害が大きい順に
「金銭 → 本人確認情報 → 位置・連絡先」であり、その順で守りを厚くする。

> ⚠️ 「絶対に安全」は存在しない。ここに書くのは**多層防御**の各層と、その層が破られたときに
> 何が残るかである。第三者によるペネトレーションテストは本番公開前に別途実施すること。

---

## 0. 原則

1. **持たない**のが最強の防御。カード番号・本人確認書類は自社に保存しない。
2. **信頼しない**。入力・外部レスポンス・自社の別レイヤも検証する。
3. **静かに壊れさせない**。誤用は例外で落とす（例: トランザクション外のロック取得）。
4. **記録する**。金銭と人の処遇に関わる操作は監査ログに残す。

---

## 1. 金銭（最優先）

### カード情報を一切保持しない
- カード入力欄は **Stripe Elements（別オリジンの iframe）**。カード番号は当アプリの DOM にも
  サーバにも入らず、ブラウザから直接 Stripe へ送られる。届くのは PaymentMethod ID だけ。
- **PCI DSS のスコープを最小化**する設計。`WebSecurityTest` が「カード情報らしきカラムが
  DB に存在しないこと」を全テーブルに対して検証している（回帰防止）。
- 公開可能キー（`pk_`）だけをビューへ渡す。秘密鍵（`sk_`）と Webhook シークレット（`whsec_`）が
  ブラウザに出ていないことを `CardPurchaseFlowTest` が検証する。

### テストは実資格情報を見ない
`.env` に実キーが入ったままテストを流すと、Fake ではなく実アダプタが選ばれ、
**テストが本物の Stripe に課金しに行く**（レート制限のテストは購入を6回叩く）。
`tests/bootstrap.php` が `$_SERVER` / `$_ENV` / `getenv()` の3つとも空にして入口で断つ。
`NoRealCredentialsInTestsTest` が隔離を常時検証している。

> phpunit.xml の `<env force="true">` だけでは不十分。PHPUnit が消すのは `getenv()` と
> `$_ENV` だけで `$_SERVER` が残り、Laravel の `env()` は `$_SERVER` を先に見るため、
> シェルで export された実キーがそのまま通る。

### 3Dセキュアの確定はサーバが決める ★重要
3Dセキュアは「保留 → ブラウザで認証 → 確定」の2段階になる。確定時に
**クライアントの申告を一切信用しない**設計にしている。

- 確定要求に決済IDを含めさせない。**どの決済を確定するかはサーバのセッションが持つ**
  （他人の決済IDや別商品への差し替えができない）
- 確定時に PSP へ問い合わせ、**状態と金額の両方**を突き合わせる
  （やらないと「100円払って10,000P受け取る」が成立する）
- 台帳の冪等キーは**決済参照ID から作る**ため、同じ決済で二度ポイントが増えない
- 認証前にポイントは一切付与しない

### 二重課金・二重計上を防ぐ
| 層 | 対策 |
|---|---|
| PSP | 冪等キーを Stripe にも渡す。リトライしても課金は1回 |
| 台帳 | `point_transactions.idempotency_key` に UNIQUE 制約。二重計上は DB が弾く |
| 順序 | PSP 課金 → 成功時のみ台帳へ追記。**失敗時は台帳に何も書かない**（テスト済み） |

### 残高の競合状態（二重与信）を防ぐ ★重要
「残高を確認 → 引き落とす」は、ロック無しだと同時リクエストで両方が確認を通過し、
**残高以上に使えてしまう**。これは実在した不具合で、以下で修正済み。

- `WalletRepository::loadForUpdate()` がウォレット行を `FOR UPDATE` で掴む
- 金銭が動く全経路（呼び出し作成・延長・おひねり・出金申請）がこれを使う
- **トランザクション外で呼ぶと `LogicException`**（ロックが即解放され無意味になるため）
- 検証: `LedgerConcurrencyTest` / `LockedReadGuardTest`

### Webhook（外部から認証なしで叩ける唯一の口）★重要
`POST /webhooks/stripe` は認証も CSRF も無い。**署名検証だけが門番**なので、
突破されれば「架空の返金」「架空の入金」を注入できる。以下で固めている。

| 対策 | 内容 |
|---|---|
| 署名検証 | `Stripe-Signature` を**生ボディ**に対して HMAC-SHA256 で検証（`StripeSignatureVerifier`） |
| 定数時間比較 | `hash_equals`。先頭一致の長さから秘密を推測させない |
| リプレイ拒否 | タイムスタンプのズレが ±300 秒を超えたら拒否 |
| **設定漏れ＝拒否** | `STRIPE_WEBHOOK_SECRET` 未設定なら**常に false**。「未設定だから素通し」を作らない |
| 冪等 | `webhook_events(provider, event_id)` の UNIQUE 制約。再送は 200 を返して何もしない |
| 失敗時は 5xx | 処理中に例外が出たらイベント記録ごとロールバック。**200 を返して再送を止めない**（返金の取りこぼし＝損失） |
| CSRF 除外の限定 | 除外パスは `webhooks/stripe` 1本のみ。増減はテストが検出する |

検証: `StripeWebhookTest` / `StripeSignatureVerifierTest`（署名偽造・ボディ差し替え・リプレイ・
シークレット未設定・再送冪等をそれぞれ固定）。

### 返金・チャージバックでポイントを必ず回収する
返金されたのにポイントが残ると、そのぶんが丸ごと損失になる。

- 購入時に `point_purchases`（`charge_ref` UNIQUE）を残し、**どの購入を回収するか特定できる**ようにする
- `charge.refunded` は `amount_refunded`（累計）で按分。端数は**切り上げ**て多めに回収する
- `charge.dispute.created`（チャージバック）は争う／争わないに関わらず**全額回収**
- すでに使い切られていた場合も**回収は行う**。残高がマイナスになるのを許容し、
  `refund.balance_shortfall` をエラーログと監査ログに残して運営が対応する
  （黙って取りこぼすより、負債として見える方が安全）
- 未設定の `STRIPE_WEBHOOK_SECRET` は `pato:release-check` が公開前に止める

### 残高は台帳の合算
残高カラムを持たない。`point_transactions` の追記のみで表現するため、
**書き換えによる残高の改ざんができない**。監査時に全履歴を再現できる。

### レート制限
| 対象 | 上限 | 理由 |
|---|---|---|
| ポイント購入 | 5回/分・50回/日 | **カードテスト**（盗難カードの有効性確認）に悪用させない |
| 呼び出し作成・延長・おひねり・出金申請 | 20回/分 | 与信の乱発を抑える |
| ログイン | 5回/分（IP と メールの両方） | 総当たり／アカウント狙い撃ちの両方に効かせる |
| 本人確認 | 10回/時 | 生年月日の総当たりを防ぐ |
| 通報 | 20回/時 | 嫌がらせ通報の連投を抑える |
| SOS | 10回/分（緩め） | **押せない方が危険**。連打はサービス側でまとめる |
| Stripe Webhook | 300回/分（緩め） | 障害復旧時の大量再送で詰まらせない。門番は署名検証 |

## 2. 本人確認情報・PII

- **書類・顔画像は自社に持ち込まない**。eKYC ベンダで処理し、結果（確認可否・18歳以上か・
  参照ID）だけを受け取る。生年月日は年齢判定に使い、**保持しない**。
- 保存する生年月日（`identity_verifications`）は**暗号化**（`encrypted` キャスト）。
- SOS の位置メモ・購読キー・パスワードは**シリアライズから除外**（`$hidden`）。
- ログは `MaskPii` プロセッサでメール・電話番号・生年月日・トークンを自動マスク。
  そもそも渡さないのが原則で、これは最後の網。

## 3. Web 層

| 対策 | 内容 |
|---|---|
| CSP | XSS でスクリプトを注入されても実行させない。`object-src 'none'`、`frame-ancestors 'none'`、`form-action 'self'`。決済は `js.stripe.com` のみ許可 |
| HSTS | HTTPS 時のみ付与（開発の平文アクセスを壊さない）。`includeSubDomains; preload` |
| HTTPS 強制 | 本番は `URL::forceScheme('https')`。プロキシ配下でも https を認識 |
| X-Frame-Options | `DENY`。**クリックジャッキングで「呼び出す」を押させない** |
| Referrer-Policy | 呼び出しIDなどを外部サイトに漏らさない |
| Permissions-Policy | カメラ・マイクを明示的に無効化 |
| CSRF | Laravel 標準のトークン検証（`web` グループ） |
| セッション | `http_only`（XSS で盗めない）、本番は `secure`、`same_site=lax` |
| パスワード | bcrypt ハッシュ。シリアライズから除外 |

## 4. 認可

- ロールは `guest` / `cast` / `admin` / `system`。`role` ミドルウェアで**入口で**弾く。
- 個別のリソースは所有権チェック（自分の呼び出し・自分のスレッドのみ）。
- **停止アカウントは呼び出し作成も参加もできない**（`AccessGate` / `participate`）。
- 管理操作は `role:admin` に限定し、**すべて監査ログに残る**。

---

## 5. 監査ログ

`audit_logs`（追記のみ）に「誰が・いつ・何を」を記録する。

- アカウント停止／解除
- 精算の承認・送金・却下（金額つき）
- 料金・テイクレートの変更（**変更前後**）
- 審査の承認・却下（付与クラス）

context に PII を入れないこと。
